## 概要

「リンク先URL（絶対に必要な文字列）」と「自由に変えていい部分の制約」を指定すると、
その制約内で **元画像に一番近い模様になる文字列** を総当たりで探し、候補を並べるツール。

- **線形解法（既定）**: QRの「ペイロードのビット → モジュール」は GF(2) 上のアフィン写像
  （`M(x) = M0 XOR Σ xi・Di`）なので、目標パターンから文字列を逆算できる。
  輪郭に近く重みの大きいモジュールから順に方程式を立ててガウス消去で解く。
  基底はマスクに依存しないため、8マスク分の右辺を1回の消去でまとめて処理する
- **ランダム探索**: 文字種・長さを自分で指定したいとき用。一致率は50%＋数ポイントが上限
- 自由部分は `H-O / h-o` の16文字（`0x48 XOR {1,2,4,0x20}` というビット部分空間になっている英字）を使い、
  1文字あたり4ビットの自由度を確保する
- 描画は「画像と一致しているモジュールのドットを薄くする」ハーフトーン方式で、写真を透けさせつつ読み取りやすさを保つ
- 出力ごとに jsQR で自動デコードして「読取OK / 読み取れず」を判定

実測（合成写真・型番6・ECC L）: ランダム探索 53% に対し線形解法は **71.8%**、所要時間は 0.2 秒。
- 画像はすべてブラウザ内で処理され、外部に送信されない

## サーバーなしで任意のページに飛ばす仕組み

多くのサイトは知らないクエリパラメータを無視するので、
`https://example.com/page?qr=xxxxxx` の `xxxxxx` を自由部分にすれば、
リダイレクタを持たなくても「リンク先は任意・見た目は自由」を両立できる。
自前のリダイレクタがある場合はテンプレートモードで `https://example.com/r/{}` のように書ける。

## 依存

- `/assets/qrcode.min.js` — QRコード生成（node-qrcode / MIT）
- `/assets/jsqr.min.js` — 読み取り検証（jsQR / Apache-2.0）

画像埋め込みQRコード最適化

固定文字列を保持し、変更してよいASCII文字列を探索して、元画像に近い正規QRコードを作ります。さらに、同じ文字列に読み取れることを検証した加工版も別に表示・保存できます。画像・文字列はブラウザ内で処理します。

使い方

  1. アプリを開くか、単一HTML版を保存して開きます。単一HTML版は通信なしで動作します。
  2. 元画像と固定する文字列を指定します。可変部分には、変更してよい文字・長さを設定します。URLの例は固定部分 https://example.com/# と可変部分の組み合わせです。実際のURLで変更してよい箇所を確認してください。
  3. 通常は「指定した文字種を使う（Byte）」で、URLとして有効な文字種と長さを設定します。URLを一文字も変えられない場合は、可変部分を削除してURL全体を固定します。
  4. 必要な領域をブラシ・矩形・円形で指定します。「できるだけ黒／白」は目標、「絶対黒／白」は必ず満たす条件です。重要度0の領域は探索スコアから除外します。
  5. 「生成する」を押し、検証を通過した候補を比較します。初期値はURL-safe文字128文字・ECC M・49×49マス、マスク8通り、20秒です。「生成後に加工版も作る」が有効なら、各候補の加工版も検証します。
  6. 正規版・加工版のそれぞれのボタンからPNGまたはSVGを保存します。実際に復号される文字列は両方同じです。白い余白は4マス以上です。

固定部分はUTF-8の日本語に対応します。可変部分はASCIIで、複数配置でき、禁止文字も指定できます。任意の長い数字列が使える場合に限り、Numeric方式を選択できます。この方式では、禁止文字を除いた許可集合が0〜9をすべて含む可変部分だけを数字に絞ります。「このサイズで数字を最大限使う」は、その最後の可変部分の長さも容量いっぱいに変更する操作です。通常の生成や加工はこの変更を必要としません。

生成後の加工版

正規QRの生成・検証後、正規版の文字列をそのまま読み取れる加工版を作ります。読み取り対象のURL、文字種、文字数、Version、ECC、Maskは変えず、一部のマスだけを目標の白黒へ変更します。元の正規版も残します。

  • 誤り訂正（RS）の各ブロックについて、変更した8bit単位の語数を管理します。同じ語の中で複数マスを変更しても、使う訂正能力は1語分です。DENSO WAVEの説明に従い、訂正語数から訂正可能な誤り語数を計算します。
  • 訂正可能な語数の50%／70%／90%を加工の上限として選択できます。初期値は70%。どのブロックにも少なくとも1語分の余力を残します。この割合は塗れる面積の割合ではありません。
  • 位置検出・位置合わせ・タイミング・形式・Version情報と余りビットを保持します。絶対黒白の指定と重要度0のマスも変更しません。
  • 1マス2／4／8px・余白4マスの画像からjsQRで復号し、正規版とバイト列が完全一致する場合だけ採用します。検出に失敗したら加工量を減らして再検証し、成功する改善版がなければ加工版の保存は提供しません。
  • 保存時にも、指定した寸法・余白の画像を読み戻して復号します。加工版のファイル名には -artistic- が付きます。

加工量と残る訂正余力は結果の詳細に表示します。加工は汚れなどに使える誤り訂正の余力を消費します。自動検証に成功しても、実機カメラ・印刷・遠近変形など任意の条件での読み取りを保証するものではありません。

精度の改善

  • QR容量を絵に使う：数字3文字を10bitで符号化し、初期求解ではそのうち9bitを有効な数字の範囲で変更します。同じQRサイズに多くの自由度を入れられます。マスクと目標に応じて固定するbitを選び、必要に応じて0〜999全体から絶対指定を満たす候補・局所改善を探します。末尾1〜2文字にも対応します。この方向性はQArt Codesを参考にしています。
  • 指定をそのまま保持：元画像、画像変換、ソフト目標、Float32の重要度、絶対指定を別々の状態として管理。長さ・Versionの比較や中断で失いません。重みをキャンバスの色から復元しません。
  • 文字集合を広く利用：初期求解は許可集合内の最大アフィン部分空間を厳密に選択。その後は許可文字全体による局所改善を行います。初期集合で絶対指定が解けない場合も、7bitの線形式と許可集合による探索を試みます。
  • 初期の判断を見直す：重要度順の初期求解だけで止めず、絶対指定を守る自由度で単独・ペア変更を試します。残存自由度が8bit以下なら、時間内で全組合せを比較します。
  • 濃淡を探索の指標にする：画素の重要度付き一致と、2・4・8マス単位の濃淡誤差を組み合わせます。評価割合0なら画素一致のみです。「探索スコア」は候補を並べる指標で、人による見た目の再現率ではありません。
  • 見え方の弱点を表示：結果には全マスの画素一致、目標の黒領域を黒くできた割合、背景の白領域へ黒が混入した割合を分けて表示します。黒領域の再現は高いほど、背景への黒混入は低いほど目標に近くなります。これらは重要度を掛けない集計です。
  • 範囲を比較：Mask 0〜7、4方向、指定Version範囲、可変長の粗探索と上位長さ近傍の細探索に対応。1条件で絶対指定が解けなくても他の条件を続けます。
  • 計算を共有：RS符号の線形性から差分を作り、マスク間で共有。実エンコーダとのセルフテストも実行します。従来の「1長さ・1パス・16サンプル・マスク比較OFF」への自動変更は廃止しました。

Versionを変えるとき、目標と重要度は元の編集座標から投影します。絶対指定は重なるすべてのマスへ投影し、絶対黒と白が重なったVersionは除外します。選択範囲を黙って捨てたり緩めたりしません。

時間は目安です。計算単位の完了と最終検証には追加時間がかかることがあります。中断はWorkerを停止し、入力を保持します。探索はヒューリスティックで、全体最適解や、見つからなかった場合の解の不存在を保証しません。

出力の検証

正規版の各候補に次の検証を必須にしています。加工版には上記の別の検証を適用し、「エンコーダと差分0」「RS誤り0」として扱いません。

検証 合格条件
固定文字列・許可文字 固定部分のバイト列が一致し、可変部が許可集合内
絶対黒・絶対白 保存用の白黒配置で全件達成
元エンコーダ 求解結果との白黒差分0
独立エンコーダ（Nayuki） Byte／Numericの区切り・Version・ECC・Maskを揃えて差分0
出力画像の再読込 モジュール中心を読み戻して差分0
独立デコーダ（jsQR） 画像から検出・復号したバイト列が完全一致
RSブロック 各ブロックの誤り語数0、非零シンドローム0

PNG／SVG保存時は、選んだ寸法と余白でもCanvasの画像を再読込・復号します。SVGは同一行列の正方形を描きます。自動テストではPNGへの符号化・再読込と回転・縮尺も確認します。実機カメラ、印刷、汚れ、遠近変形での読み取り評価は別途必要です。

再現できる検証

npm ci --prefix tools/image-qr --ignore-scripts
npm --prefix tools/image-qr test
node tools/build-image-qr.mjs --check
npm --prefix tools/image-qr run benchmark
npm --prefix tools/image-qr run benchmark:numeric
npm --prefix tools/image-qr run benchmark:artistic

Node.js 24を使用。CIで構文、回帰テスト、単一HTMLの再現性を確認します。テストには実エンコーダとの写像一致、全Version／ECCのRS構成、独立復号、ByteとNumericの混在、最大容量・桁数境界・先頭ゼロ、文字集合の取りこぼし、入力状態の保持、オフラインWorker、中断後の再生成を含みます。UIのデータフローテストはjsdom上で実行し、Canvasは模擬しています。ブラウザでの画面表示確認とは別です。

加工版は4つのECCレベル・4方向、構造と絶対指定の保持、ブロックごとの予算超過、復号失敗時の非出力、独立したPNG／SVGダウンロードと復号文字列の一致を回帰テストしています。

正規版と加工版の比較では、QRの文字列・マス数・ECC・Maskをすべて揃えたまま加工の効果を確認できます。可変部分なしの固定URLも含みます。

数字方式の比較結果と検証画像では、円形・斜線・ハートを同じ49×49マス、ECC M、固定URL、20秒の予算で比較します。両方式で容量を最大限使うため、可変部分の文字数は異なります。

以前のByte方式の比較も残しています。こちらは旧貪欲法と追加探索の比較で、画素一致の改善は0.08〜0.67ポイントでした。数字用符号化の改善幅とは別の記録です。

ファイル構成と更新

  • assets/image-qr-engine.js：文字集合解析、QR写像、最適化、検証、SVG生成。
  • assets/image-qr-worker.js：計算の実行と進捗通知。
  • assets/image-qr-ui.js / assets/image-qr.css：入力状態、画像変換、領域編集、画面、保存。
  • assets/vendor/image-qr/：独立エンコーダ・デコーダとライセンス、固定したソース版。
  • tools/image-qr/：回帰テスト・比較用の旧方式とベンチマーク。
  • tools/build-image-qr.mjs：すべての依存とWorkerを埋め込んだ単一HTMLの生成。

ソースを変更したら node tools/build-image-qr.mjs を実行し、生成した image-qr-optimizer.html も一緒にコミットします。外部CDN、追加ファイル、サーバーは単一HTML版に不要です。Jekyll版は既存のGitHub Pagesプレビューに対応しています。
